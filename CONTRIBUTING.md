# Contributing to EduLingua

Thank you for your interest in contributing to EduLingua! We welcome contributions from everyone. This guide will help you get started.

## How to Contribute

### Reporting Bugs
If you find a bug, please:
1. Check if the issue has already been reported
2. Create a new issue with a clear title and description
3. Include steps to reproduce the bug if possible
4. Attach screenshots or code samples when relevant

### Suggesting Enhancements
We welcome suggestions for new features! Please:
1. Use a clear, descriptive title
2. Provide a detailed description of your suggestion
3. Explain why this enhancement would be useful
4. List any alternative solutions you've considered

### Creating Content
We're always looking for new educational content! To contribute:
1. Fork the repository
2. Create a new branch for your content
3. Add your lesson following the existing HTML structure
4. Test the lesson on different devices
5. Submit a pull request with a description of your additions

### Code Improvements
If you want to improve the code (HTML, CSS, JavaScript):
1. Fork the repository
2. Create a new branch (`git checkout -b feature/improvement-name`)
3. Make your changes
4. Ensure your code follows the existing style
5. Test thoroughly
6. Create a pull request

## Content Guidelines

### For New Lessons
- Follow the existing HTML template structure
- Use semantic HTML5 tags
- Include:
  - Clear introduction
  - Well-organized sections
  - Examples for each concept
  - Practice exercises when possible
  - Simple language that's accessible
- Ensure content is accurate and up-to-date
- Include both English and Bangla where relevant

### Writing Standards
- Use clear, simple language
- Break content into digestible sections
- Use examples to illustrate concepts
- Proofread carefully for grammar and spelling
- Cite sources for factual information

### Styling
- Follow the existing color scheme
- Use consistent typography
- Maintain responsive design for mobile devices
- Test on different screen sizes

## Pull Request Process

1. Update the README.md with details of any new features
2. Ensure all links work correctly
3. Test your changes thoroughly
4. Write a clear pull request description
5. Wait for review and feedback
6. Address any requested changes

## Code Style Guidelines

### HTML
- Use semantic elements (section, article, nav, etc.)
- Proper indentation (2 spaces)
- Descriptive class and id names

### CSS
- Use CSS variables for colors
- Mobile-first responsive design
- Clear, organized commenting
- Avoid unnecessary specificity

### JavaScript
- Keep code simple and readable
- Use descriptive variable names
- Add comments for complex logic
- Test across different browsers

## Development Setup

1. Clone the repository
2. Create a new branch for your work
3. Make your changes
4. Test locally in your browser
5. Commit with clear messages
6. Push to your fork
7. Create a pull request

## Questions?

If you have questions about contributing:
- Check the README.md
- Review existing issues and discussions
- Create a new issue with your question

## Code of Conduct

- Be respectful and inclusive
- No harassment or discrimination
- Constructive criticism only
- Help others learn
